# 多 WAN 测试包真机验证清单

适用测试包：LabProbe App `0.14.13 build357`、Hub `0.14.8`、LabRelay `0.2.81`。

## 验证边界

- 本清单需要一台实际连接两条可上网线路、且 WAN/WAN1 均在线的路由器。
- 自动化测试和 Test Bundle 不等于双 WAN 真机通过；在完成本清单前，双 WAN 功能状态为“待实机验证”。
- 验证过程中不要启用路由器自身的负载均衡、故障切换、策略路由或 mwan3。LabProbe 只做线路识别、展示和显式绑定，不改变现网出口策略。
- 不要删除现有端口映射、DDNS、STUN、WireGuard 或 TCP 规则。需要变更绑定时先记录原值，验证后恢复。
- BE50 当前离线时只验证 ARMv7 包能否安装和自报版本，不把离线设备标记为实机通过。

## 一、验证前记录

- [ ] 备份 Hub 数据与路由器现有配置。
- [ ] 记录两条线路的 WAN ID、物理端口、连接方式、IPv4/IPv6、网关和 DNS。
- [ ] 记录现有规则及其 `wanId`；旧规则没有 `wanId` 时按 WAN 处理。
- [ ] 确认 APP、Hub、Relay 的版本分别为 `0.14.13 build357`、`0.14.8`、`0.2.81`。
- [ ] 确认 Test Bundle 的 APK 签名校验、Hub 镜像架构和 Relay ARM64/ARMv7 校验文件均通过。
- [ ] 记录验证前的默认路由、主 WAN 和路由器总上/下行计数。

## 二、单线在线场景

保持 WAN 在线、WAN1 离线。

- [ ] 首页、路由器状态、DDNS、STUN、TCP 压测、固件测速和 NAT 诊断不显示 WAN1 离线选项，也不显示额外不可用提示。
- [ ] 上述日常页面不出现多 WAN 选择器，操作流程与单 WAN 版本一致。
- [ ] WAN 始终排在第一位，并作为新建 DDNS、映射、UPnP、STUN、TCP 和测速任务的默认线路。
- [ ] 首页和网络详情顶部总上传、总下载仍是路由器聚合统计，不被改成 WAN 单线统计。
- [ ] 设置页和物理端口页仍显示 WAN1 已配置但离线的真实状态。
- [ ] 一条原有 WAN1 绑定规则仍保留 `wanId=wan1`，APP 不把它改成 WAN，也不自动切换出口。

## 三、双线在线场景

让 WAN 和 WAN1 同时在线，等待一次现有刷新周期。

- [ ] 日常页面自动出现 WAN/WAN1 选择器，顺序始终为 WAN 在前、WAN1 在后。
- [ ] 选择器不按速率、负载或默认路由重新排序。
- [ ] WAN 仍为新建任务的默认值；用户显式选择 WAN1 后，新建请求携带 `wanId=wan1`。
- [ ] 物理端口、逻辑接口、PPPoE/VLAN、IPv4/IPv6 与两条线路一一对应，没有串线。
- [ ] 路由器总速率保持聚合值；逐 WAN 速率分别显示且不与聚合值重复累计。
- [ ] 刷新、切页、APP 前后台切换和 Hub 重连后，两条线路不会因旧快照而消失或交换地址。

## 四、功能专项

### 固件端口映射与 UPnP

- [ ] 新建 WAN 映射后，Hub 规则、Relay 同步结果和防火墙入站接口均为 WAN。
- [ ] 新建 WAN1 映射后，上述三项均为 WAN1，且从 WAN1 公网侧访问成功。
- [ ] 编辑映射的端口、协议或目标时，固件更新请求不会把 Hub 专属 `wanId` 字段写回固件旧规则。
- [ ] 同步对账能识别仅 `wanId` 不同的两条规则，不会误判为相同。
- [ ] WAN1 离线时，已有 WAN1 映射保留原绑定且不迁到 WAN；日常页面不显示灰色 WAN1 选项。
- [ ] UPnP 的单线/双线显示与端口映射一致。

### DDNS、STUN、TCP 与测速

- [ ] WAN1 DDNS 更新取得 WAN1 出口地址，Relay 发布前完成路由、源地址和绑定设备复核。
- [ ] STUN 使用 WAN1 时，实际连接源地址与所选 WAN1 一致。
- [ ] TCP 压测启动、轮询和停止请求始终携带同一个 `wanId` 和 `taskId`。
- [ ] 固件测速分别对 WAN/WAN1 启动时，任务请求和结果线路一致。
- [ ] WAN1 无能力或离线时不会出现在测速选项里，但设置页仍保留真实配置状态。

### NAT 诊断

- [ ] WAN1 诊断成功时，请求线路、固件检测线路、结果 `wanId` 和 `detectedInterface` 均为 WAN1。
- [ ] 固件实际返回 WAN 而请求为 WAN1 时，任务失败并标记 `wan_mismatch`，不保存为 WAN1 成功结果。
- [ ] 固件未报告实际出口而请求为 WAN1 时，任务失败，不猜测线路。
- [ ] 旧的带时间戳结果、上一任务结果和迟到轮询不能覆盖当前任务。
- [ ] 同时发起第二次 NAT 诊断返回 `409 NAT_DIAGNOSTIC_BUSY`，不产生第二个固件任务。

### WireGuard

- [ ] 自动端点的来源线路、`ddnsRecordId`、名称、启用状态和更新时间在 Hub/Relay 往返后保留。
- [ ] WAN1 端点更新不会把既有 WAN 端点或手动 profile 改成自动 profile。
- [ ] WAN1 离线时保留上一条可用端点，不自动改成 WAN。

## 五、断线与恢复

- [ ] 断开 WAN1 后，日常页面直接隐藏 WAN1，不需要等待 60 秒。
- [ ] 已有 WAN1 规则和绑定保持不变，不自动迁移到 WAN。
- [ ] 恢复 WAN1 后，选择器恢复，顺序仍为 WAN、WAN1。
- [ ] 重复三次断线/恢复，WAN 身份、地址和规则绑定均无串线。
- [ ] 验证结束后恢复验证前的规则绑定与路由器配置，并确认默认路由未变化。
