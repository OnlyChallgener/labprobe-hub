# BE72 eWeb HUB 页面

## 功能与页面

“更多”的原生第二列菜单底部新增 HUB 图标，包含三项：

| 菜单 | 原生路由 | 功能 |
| --- | --- | --- |
| WireGuard | `/alone/hub/wireguard` | 路由器服务端配置、公钥、客户端、连接地址、握手与隧道流量 |
| TCP 峰值测试 | `/alone/hub/tcp_peak` | 由路由器 Relay 发起的 IPv4／IPv6 连接测试，包含启动、停止、连接趋势和资源释放状态 |
| DDNS | `/alone/hub/ddns` | 我们的 DDNS 配置、服务商凭据、记录类型、增删改、启停、立即更新及批量操作 |

组件直接复用固件的 Vue 2.6.14、Element UI 和 ECharts。表单、按钮、对话框、表格沿用原生样式；图形采用网络测速的青蓝和绿色。已有网络看板图例修复保留。

本次用户反馈后的尺寸：WireGuard 地址输入框 340px，TCP 地址、协议选择框与数字输入框均为 220px；DDNS 弹窗 740px、内部表单 540px 居中，两侧留白。窄屏限制弹窗宽度，图形纵向排列。

DDNS 地址来自路由器 Relay 的 `ddnsAddress`，由 Hub 的 `accept_address` 接收。现有 Relay 在路由器上探测公网出口和本机网络地址；前端不额外探测 NAS 或浏览器出口。页面紧凑显示 IPv4／IPv6，去掉取址说明小字。修改弹窗读取已保存凭据，Secret 默认遮住，可点击原生眼睛按钮显示。

## 接入和行为

浏览器使用当前 eWeb 登录会话调用 `/cgi-bin/luci/api/labprobe`，不增加另一套登录或授权界面。路由器代理仅支持固定的操作和固定的 BE72 Hub；令牌保存在路由器 `/etc/labprobe/eweb-hub.curl`，权限 0600。

凭据读取是新增的、经过 Hub 授权的 `/api/ddns/<id>/credentials`，设置 `Cache-Control: no-store`；正常 DDNS 列表不包含明文凭据。原生 RPC 包装器捕获异常，避免进入固件会记录参数的异常日志分支。

WireGuard 保存携带编辑时的配置版本，防止并发修改覆盖。自动刷新保留未保存草稿，旧请求不能覆盖刚执行的操作；离开页面终止请求和定时器。TCP 运行时输入字段锁定，停止按钮保持可用。

## “全点不了”的修复（20261008-2）

根因在原生应用入口 `NHnr`：固件重新定义了 `Promise.prototype.finally`，成功和失败分支均缺少外层 `return`。HUB 请求虽然返回 HTTP 200，调用 `.finally` 后响应却变成 `undefined`；读取函数随后报错，`loaded` 无法变为 true，表单、添加和开始按钮持续禁用。先前仅加载组件库的渲染测试未执行这个入口，因此未覆盖该问题。

HUB 现在通过自己的 `complete` 收尾函数保留返回值和异常，不修改固件的全局 Promise。同步初始化失败同样释放读取／操作状态；普通请求 12 秒超时，DDNS 写操作 35 秒超时，退出页面终止未完成请求。会话恢复补齐原生 SN Cookie 的读取。

本机 `labwg0` 接口实际已启用，但固件缺少 wg 命令行工具，Relay 的命令行能力块仍返回空接口。路由器代理读取该接口的启用标志、接收／发送字节和采样时间，页面优先使用这些本机数据。公钥使用当前配置版本的成功应用回执；未提供握手时间时仍显示 `--`，不推测客户端连接状态。

HUB 图标改为圆角线框拓扑图，源文件为 `eweb/hub-icon.svg`，沿用原生菜单的灰色、悬停色和选中色。跟进部署备份为 `/etc/labprobe/backups/eweb-hub-fix-20261008-122905`。此次更新未重启路由器、Relay 或 Hub。

## STUN、握手、地址历史及 TXT 显示修复（20261008-4）

### WireGuard

实际配置存在 5 个连接地址，其中 4 个 STUN 配置由不同 APP 客户端建立，但引用同一条 STUN 规则、监听端口和地址。页面现在按来源、绑定规则、端口及启用状态合并为 2 行；保留各 APP 配置的原编号和版本。组内修改作用于全部成员，删除仍需用户确认后保存；不会在加载时删除后台配置。不同 STUN 规则即使暂时解析成相同地址，也不会合并。

接收／发送流量、客户端数量和最近握手的数字缩为 20px。新增中文“在线用户”页签，显示名称、状态、实际地址、隧道地址、最近握手及双向累计流量。切回 WireGuard 后，趋势图重新绑定当前图形容器。

本机没有 wg 命令。增加一次性只读助手 `/usr/libexec/labprobe-wg-status`，直接查询内核 Generic Netlink，读取公钥、端点、允许地址、真实握手和计数器。源文件位于 `eweb/wg-status/`，静态编译为 aarch64 musl；兼容 BE72 内核不带状态体的 NLMSG_DONE。读取限制为 2 秒、64 个客户端和 1MB 总报文，输出仅包含公开状态字段。

在线判定要求本机采样新鲜、接口启用，并且最近 180 秒发生真实握手，或最近 90 秒收到认证数据包。接收字节的实际增长记录在路由器临时缓存中；历史累计流量和仅发送字节不能证明用户在线。内核未提供握手时显示“未提供”，不使用流量时间冒充握手时间。实机验证已返回一个在线客户端及真实握手时间。

### TCP 地址历史

使用原生自动补全输入框，宽度与其他字段一致。失焦、选择地址及开始测试时保存有效地址，最多 5 条，按最近使用排序；空白、大小写、域名尾点和 IPv6 表示差异会规范化去重。历史项可点击小叉删除，并保存在当前浏览器、当前路由器的独立存储中。

### DDNS

之前解析值直接拼接所有 published 字段。TXT 配置因此混入以前 A／AAAA 的发布值；那条 IPv6 是历史发布元数据，不是当前探测到的 IPv6。页面现在只渲染 recordTypes 选定的发布值，TXT 实机结果仅为 `111.23.167.101:12591`；当前 IPv6 不可用仍显示 `--`。

## 用户列表稳定性、字号和 DDNS 对齐（20261008-5）

### 固定用户名单与状态

此前“在线用户”只显示最近活动的内核客户端。活动超时或一次读不到客户端状态，就会把整行过滤掉；这是本次确认的列表消失原因。现在以服务端已配置的公钥名单固定显示行，运行状态按公钥合并；离线仍保留名称、地址、流量及已知真实握手。读取失败保留上次快照，状态数据超过 90 秒未更新后显示“待更新”，不会把读取失败当作离线或删除。

在线判定改为接口启用，且最近 300 秒有真实握手或认证接收活动；已经在线的客户端额外保留 30 秒缓冲。这个时间窗口是页面状态策略，并不是 WireGuard 的即时登录／退出回执。累计流量、仅发送数据及隔很久才发现的历史接收增长不算当前活动。路由器接收活动缓存新增 observedEpoch，只有前次采样距本次不超过 90 秒时，增长才记录为当前接收活动。

页面保留实际握手时间，流量活动不替代握手时间。客户端计数器回落时清除旧会话状态；服务端接口变化时清除旧接口缓存。刷新页面加载的首次报告仅使用真实内核数据。

### APP 用户身份

同一 BE72 上的客户端按公钥匹配。保留同一份 WireGuard 配置和密钥，修改 APP 登录信息后仍能匹配原客户端；重新创建配置会生成新密钥，形成另一条记录。APP 的密钥存储命名空间包含工作区及 Hub 地址，切换设置时也可能选中另一份已保存密钥，因此不能只凭账号或设备名称认定为同一用户。使用相同私钥的原配置连回同一网关，会匹配原公钥记录。

旧记录默认保留为离线，确认不再使用时由用户删除。删除服务端客户端配置会撤销该密钥的连接资格；连接地址的分组显示不删除服务端客户端。

### 读取恢复

12 次从 BE72 到 Hub 的只读请求均返回 HTTP 200 和完整配置，耗时从约 0.2 秒到 3.7 秒，本轮没有复现用户看到的空响应。不能据此认定 Hub 偶发失败的根因已查明。

WireGuard 配置读取使用一次 4 秒请求；遇到连接失败、无效成功响应或 5xx，增加一次 2 秒只读重试。两次都失败时，可以使用 120 秒内的路由器 RAM 配置缓存，同时继续查询真实内核状态，页面明确显示“数据恢复中，已保留上次数据”。缓存绑定路由器名称和 Hub 地址；失败不续期，过期、其他路由器、鉴权失败均不使用。成功修改／删除 WG 配置后使该缓存失效，写操作不会重试或重放。

### 原生排版

WG 汇总和 TCP 底部汇总数值统一缩为 16px，输入框字号保持原生样式。原生 DDNS 的 CustomHosts 组件为各普通列设置 align="center"；我们的 DDNS 同样将表头与内容居中，操作按钮随列居中并保持垂直居中。
