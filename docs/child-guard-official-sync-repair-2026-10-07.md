# 儿童守护官方名单同步修复记录

## 范围与原因

0.13.83 的本地 `dev_config add/del` 回执不能证明官方账号名单已变更。固件以后接收官方完整名单时，会重新创建云端仍保留的成员。因此本地删除 iQOO15 后，它再次出现；本地新增 iPad 时，官方名单没有该设备。

官方统计的约五分钟上报批次与名单增删不同。修复不等待统计批次，也不通过延长 APP 超时解决名单分歧。

## 已验证的账号接口

官方服务固定使用 `https://shinyaapp.ruijie.com.cn`，验证 TLS 证书、拒绝重定向。密码只用于这次授权，不落盘；授权令牌按各 Hub 的密钥分别加密保存，文件权限 0600。

| 操作 | 路径 | 必要约束 |
| --- | --- | --- |
| 密码登录 | `/api/v1/base/homeUser/accountPasswordLogin` | `account/password`，不保存密码 |
| 账号网络列表 | `/homewlan/apMonitor/getProjectList2` | `buildingId` 是实际 projectId |
| 网络路由器列表 | `/homewlan/homeAp/getDeviceInfoList2` | 必须填写北京日期 `day` |
| 受守护名单 | `/api/v1/netguard/staGuard/getProtectStaListPage` | 主路由 SN、创建时间、含主路由的 mesh SN 列表 |
| 加入守护 | `/homewlan/childProtection/addSta` | `staMac` 为大写、不带冒号的 12 位 MAC |
| 解除守护 | `/api/v1/netguard/staGuard/deleteSta` | 主路由 SN 与官方 staId |
| 固件完整配置 | `/api/v1/netguard/staGuard/getSyncSetCfg/{SN}` | 与账号名单、路由器身份一致 |

新增请求使用带冒号的 MAC 曾返回 code 500；改为官方格式后 code 0，名单回读确认新增。

## 实现

- 新增 `official_child_guard.py`：官方接口客户端与持久化工作流。接受操作后返回已有 APP 支持的 HTTP 202/commandId，完成后返回官方与路由器均已确认的结果。
- 名单增删先读取官方名单，按实际 MAC 确认目标。官方写入后回读，再执行路由器命令、回读本地名单，最后再次核对官方名单。POST 响应丢失后先读名单，再决定是否补写。
- 操作按路由器与提交顺序保存。相反操作不能越过在途操作；Hub 重启后继续跟踪原操作。
- 使用官方 staId 作为本地 UID。处理没有管控规则的旧重复编号；旧编号有计划或封禁时保留规则并明确报错，不自动删除规则。
- 精确 UID 删除不携带 MAC 回退，避免旧编号消失时误删替代编号。
- 旧固件名单再次出现时，先核对官方名单。官方仍认可用户操作则修复本地；官方 APP 已有后续手动变更则采用最新官方状态。
- 每个 Hub 的主路由与原生序列号分别匹配账号归属。明确指定 BE50 的请求不能被旧代理解析器转成 BE72。BE50 的通用 eWeb 主机名 `Ruijie` 不用作机型身份。
- 不按设备名称合并不同 MAC，不操作第三个网络。
- 官方 HTTP、重试和路由器回执等待在独立工作线程内进行，不占 Hub 全局数据锁。本地快速统计继续采样。

## 部署与验收

两个 Hub 的当前运行代码均保留，只替换守护同步相关代码；两个路由器的 agent 已更新到 0.2.74，原 relay 进程、配置和 WG 连接保留。已保留容器与二进制回滚备份。

当前 0.13.83 APP 已支持该异步协议，不需要新 APK。

### BE72

- 经实际 Hub 新增接口核对 iPad，约 7.16 秒完成。官方与本地使用同一守护编号，旧重复编号不再存在。
- 经实际 Hub 删除接口解除 iQOO15，约 6.18 秒完成。官方名单由 7 台变为 6 台，其他官方成员编号不变，本地也确认删除。
- 用户在官方 APP 刷新后确认：iPad 在，iQOO15 已消失。
- 在确认没有本地计划、封禁或暂停规则需要保留后，通过固件原生 child_sync 路径重读并应用当前完整云端名单。17:54:40 完整同步后，两边仍是相同的 6 个守护编号；iPad 保留、iQOO15 不恢复。

### BE50

- 官方账号路由器序列号与该 Hub 原生序列号一致，独立授权已安装。
- 官方、Hub 儿童总览与路由器原生名单均为同一组 8 个守护编号。本轮没有对 BE50 守护成员做测试增删。
- agent 0.2.74 已运行。最后核对时本地统计采样时间在推进；没有新增流量的设备不会因此增加使用时长。

两台实时状态接口均返回 200，读取约 8–9 毫秒；BE72 儿童总览约 65 毫秒、BE50 约 142 毫秒。单次测量不代表长期网络延迟保证。

## 测试与边界

守护工作流、原有命令协议、缓存与队列的 38 项测试通过，覆盖请求断开、重启续跑、回执等待、顺序、重复编号、跨路由拒绝与旧名单恢复。

路由器整体测试中 129 项通过，另一个已有 TCP 容量预算测试失败；它读取当前运行资源，与本次守护路径无关，不将此结果写成全套通过。

官方接口来自当前官方 APP 的实际协议，不是公开稳定契约。授权过期时返回明确的重新授权提示，不保存密码自动登录。授权入口是 `/api/router/child-guard/official/auth`，需要当前 Hub 的 APP 授权；后续若增加 APP 内授权界面，应继续避免密码持久化。

BE50 的真实增删仍需在用户实际选择设备时进一步核对官方 APP；当前已验证归属、授权、名单读取与路由器组件，不能把它写成已完成 BE50 增删业务实测。
