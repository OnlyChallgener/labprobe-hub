## CPU 反馈与边界

已读取用户测试的原始结果：IPv6 两目标、126087 峰值、23.991 秒、CPU 峰值 88.05%，结束原因为显式源端口池耗尽。该值是全机 CPU 峰值，不能当成 Relay 单进程占用；另一张 58% 截图缺乏完整同条件配置，不能从两张图确认提升或退化比例。本轮网页发布未替换 Relay 二进制，现场版本及哈希已核实。

旧版极限模式在较高设定速率下允许上万待连接请求，接近 99% CPU 才减速。已部署的 0.2.77 将待连接上限收至 4096，并在 70/80/90% CPU 逐级降低新增速率。已建立连接保留，等待中的连接仍等待结果；不降低连接目标、不取消资源保护、不跳过失败确认。

降低速率可能延长到达峰值的时间。到时长上限只能称本次测得最大值；源端口或 conntrack 先耗尽代表测量路径/工具边界，不能直接称为路由器硬件极限。实际 CPU 降幅尚未通过同条件受控测试证明。

已确认 0.2.77 的三目标公网 IPv6 结果为 130264 连接、95.3947% CPU 峰值，到 Conntrack 安全阈值结束。上一轮修改未证明解决高 CPU。
